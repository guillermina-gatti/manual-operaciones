# PispIAr — A-21B.7c · Handoff de despliegue

## Contrato de configuración

### Build-time

- La API se compila sin secretos ni conexiones externas.
- La web exige `API_URL` al ejecutar el build productivo. Debe ser una URL HTTPS
  absoluta, sin credenciales, query, fragmento ni `/api`. El rewrite queda en el
  artefacto; AWS debe definir si se construye uno por ambiente o cómo se promociona.
- Ningún secreto debe usar prefijo `NEXT_PUBLIC_`.

### Runtime API

- Core: `NODE_ENV=production`, `PORT`, `DATABASE_URL`, `JWT_SECRET`, `REDIS_URL`,
  `S3_BUCKET`, `AWS_REGION` y `APP_TIMEZONE`.
- Operación: `PROCESSING_WORKER_ENABLED`, `REDIS_KEY_PREFIX`,
  `HTTP_TRUSTED_PROXIES` y `SWAGGER_ENABLED`.
- Capacidades: `FRONTEND_URL`, `INVITATION_EMAIL_PROVIDER`, variables de Resend y
  Gemini sólo cuando se habiliten esas funciones.
- Los secretos deben provenir del mecanismo aprobado de AWS, con identidad mínima,
  rotación y sin quedar en imágenes, repositorio ni logs. Ver [ejemplo de entorno](../../.env.example).

## Health checks

| Endpoint                | Respuesta                                                             | Uso                                                                     |
| ----------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `GET /api/health/live`  | Siempre `200 {"status":"ok"}` mientras atienda HTTP                   | Reinicio por proceso bloqueado. No consulta dependencias.               |
| `GET /api/health/ready` | 200 si PostgreSQL y Redis responden; 503 con `up`, `down` o `timeout` | Ingreso y retiro del balanceador. Timeout de 1 segundo por dependencia. |

Readiness ejecuta únicamente `SELECT 1` y `PING`, en paralelo. No migra, escribe ni
consulta S3, Resend o Gemini. Sus respuestas no incluyen excepciones, hosts,
credenciales ni URLs.

## Decisiones pendientes de AWS y staging

- Hosting web/API, promoción de artefactos, DNS, certificados y terminación TLS.
- Endpoints privados, CA/modo TLS y políticas de PostgreSQL y Redis.
- IP/CIDR exactos de proxies controlados para `HTTP_TRUSTED_PROXIES`; hasta entonces
  debe quedar vacío. No usar `trust proxy=true` ni asumir cantidad de saltos.
- Roles IAM, bucket/región S3, cifrado, lifecycle y permisos mínimos.
- Secret manager, rotación, cuotas y configuración de Resend/Gemini.
- Intervalos, umbrales y grace periods del balanceador para liveness/readiness.

## Evidencia y GO/NO-GO

Verificado localmente con dobles aislados: contratos HTTP 200/503, estados
sanitizados, timeout, validación de configuración, lint, typecheck y build. No se
contactaron bases, Redis, AWS ni proveedores reales.

**GO** sólo si:

- el artefacto y todas las variables pertenecen al mismo ambiente;
- migraciones aprobadas finalizaron antes del rollout;
- TLS, secretos, identidades y proxies fueron revisados;
- `/live` y `/ready` pasan en staging con dependencias reales;
- auth, cookies, rewrite web→API y observabilidad tienen evidencia sanitizada.

**NO-GO** ante configuración faltante, TLS/proxy no confirmado, secretos expuestos,
migración incierta, readiness 503/timeout sostenido o diferencias entre artefacto y
ambiente. No ejecutar resets, seeds ni reparaciones improvisadas. Seguir el
[runbook de migraciones](./A-21B.6d-runbook-migraciones-produccion.md) y conservar
la [auditoría de configuración](./A-21B.7a-auditoria-configuracion-produccion.md)
como evidencia fechada.
