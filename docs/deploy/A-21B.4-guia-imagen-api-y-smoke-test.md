# PispIAr — A-21B.4 · Construcción y verificación local de la API Docker

**Proyecto:** Manual de Operaciones Interactivo con Asistente IA — IntegrarTEC 2026
**Equipo:** A — Seguridad y Plataforma
**Fecha:** 12/11/2026
**Estado:** Construcción y prueba local verificadas. Despliegue cloud pendiente.

## 1. Objetivo

Documentar cómo construir y comprobar localmente la imagen Docker de la API NestJS antes de su utilización en una infraestructura cloud.

Esta guía no aprovisiona recursos AWS, no configura HTTPS ni constituye una prueba de producción.

## 2. Componentes

- **API:** NestJS sobre Node.js 24.
- **Base de datos:** PostgreSQL con pgvector.
- **Redis:** servicio de caché y controles de autenticación.
- **ORM:** Prisma 7.
- **Contenedor:** imagen Linux basada en `node:24-bookworm-slim`.
- **Healthcheck:** `GET /api/health/live`.

La imagen ejecuta la aplicación mediante un usuario sin privilegios (`node`).

## 3. Construcción

Desde la raíz del repositorio:

```powershell
docker build --progress=plain -f apps/api/Dockerfile -t pispiar-api:local .
```

Comprobaciones básicas:

```powershell
docker image inspect pispiar-api:local --format '{{.Config.User}}'

docker run --rm --entrypoint node pispiar-api:local -e "const fs=require('node:fs'); for (const f of ['dist/main.js','dist/generated/prisma/client.js']) { if (!fs.existsSync(f)) throw new Error('Falta '+f); } require('bcrypt'); require('@prisma/adapter-pg'); console.log('OK: API compilada, Prisma y dependencias disponibles');"
```

Resultado esperado: usuario `node` y mensaje de confirmación.

## 4. Dependencias de la prueba local

Se utilizan PostgreSQL y Redis existentes en la red Docker `manual-operaciones_default`.

Direcciones internas:

- PostgreSQL: `db:5432`.
- Redis: `redis:6379`.

Estas direcciones son exclusivas de esta configuración local; no deben copiarse a producción.

Antes de ejecutar la prueba, verificar que los contenedores están activos:

```powershell
docker compose ps
docker network ls
```

## 5. Iniciar contenedor de prueba

El siguiente comando utiliza valores de desarrollo, no aptos para producción:

```powershell
docker run -d `
  --name pispiar-api-smoke `
  --network manual-operaciones_default `
  -p 127.0.0.1:3100:3000 `
  -e NODE_ENV=development `
  -e PORT=3000 `
  -e DATABASE_URL="postgresql://app:app@db:5432/manual?schema=public" `
  -e REDIS_URL="redis://redis:6379" `
  -e REDIS_KEY_PREFIX="smoke-a21b3:" `
  -e JWT_SECRET="smoke-test-local-only-not-for-production" `
  -e FRONTEND_URL="http://localhost:3001" `
  pispiar-api:local
```

**Precauciones:**

- No ejecutar migraciones, seeds ni pruebas destructivas sobre bases existentes.
- El contenedor utiliza la base local `manual`: no es un entorno de datos aislado.
- El modo `development` permite iniciar sin un bucket S3 real.
- No utilizar estas credenciales, contraseñas ni valores de ejemplo en producción.

## 6. Verificación HTTP

Consultar estado del contenedor:

```powershell
docker ps --filter "name=pispiar-api-smoke"
docker logs --tail 50 pispiar-api-smoke
```

Consultar el healthcheck:

```powershell
curl.exe -i http://127.0.0.1:3100/api/health/live
```

Respuesta esperada:

```http
HTTP/1.1 200 OK
Cache-Control: no-store
Content-Type: application/json; charset=utf-8

{"status":"ok"}
```

Este endpoint confirma que el proceso HTTP está activo. No evalúa todas las dependencias externas ni reemplaza un readiness check.

## 7. Limpieza

Una vez terminada la prueba:

```powershell
docker rm -f pispiar-api-smoke
```

El comando elimina únicamente el contenedor temporal. No elimina las bases ni sus volúmenes.

## 9. Pendientes para despliegue

Antes de habilitar la API en producción, validar con el equipo responsable de infraestructura:

- Aprobación de arquitectura y presupuesto.
- Variables de entorno y secretos protegidos.
- PostgreSQL con TLS y migraciones controladas.
- Redis sin exposición pública.
- Bucket S3 privado y permisos mínimos.
- HTTPS, proxy inverso y política de red.
- Reinicio automático, logs y monitoreo.
- Pruebas de autenticación y autorización desde la web publicada.
- Procedimiento de rollback y recuperación.

La imagen local no constituye autorización para publicar el servicio.
